# 제공기록지 작업 복구 문구 변경 목록

계약서 문구는 유지한다. 제공기록지 분기는 `documentKind === "service_record"`로 선택한다.

## 재시도·취소·복구 안내

| 위치 | 문구 |
| --- | --- |
| 재시도 제목 | 제공기록지 생성을 재시도할까요? |
| 재시도 설명 | 재시도하면 서버에서 제공기록지를 다시 생성합니다. |
| 재시도 불가 | 이 제공기록지 작업은 지금 재시도할 수 없어요. 전자문서 작업 목록에서 상태를 다시 확인해 주세요. |
| 재시도 오류 | 제공기록지 생성을 재시도하지 못했어요. 잠시 후 다시 시도해 주세요. |
| 취소 제목 | 제공기록지 작업을 취소할까요? |
| 취소 설명 첫 문장 | 취소하면 제공기록지 생성 작업이 닫혀요. |
| 문서 생성 가능성이 없을 때 취소 설명 뒷문장(기존 문구 재사용) | 아직 보낸 문서는 없어요. |
| 문서 생성 가능성이 있을 때 취소 설명 뒷문장·상세 경고 | 이폼사인에 제공기록지가 이미 생성되었을 수 있어요. 이폼사인에서 문서 상태를 확인해 주세요. |
| 취소 불가 | 이 제공기록지 작업은 지금 취소할 수 없어요. 전자문서 작업 목록에서 상태를 다시 확인해 주세요. |
| 취소 오류 | 제공기록지 작업을 취소하지 못했어요. 잠시 후 다시 시도해 주세요. |
| RECOVERY_UNSUPPORTED 오류 | 이 작업은 수동 전송 화면을 지원하지 않아요. 전자문서 작업 목록에서 재시도하거나 취소해 주세요. |
| 제공기록지 복구 deep link | 제공기록지 작업은 수동 전송 화면을 지원하지 않아요. 전자문서 작업 목록에서 재시도하거나 취소해 주세요. |

취소 설명은 첫 문장과 해당 뒷문장을 공백으로 연결한다. 재시도 설명에도 문서 생성 가능성이 있으면 같은 경고를 덧붙인다.
문서 생성 가능성은 공통 판정 함수 `serviceRecordMayExist`로 판단한다. 아래 두 조건 중 하나라도 만족하면 참이다.

- `progressStep`이 `dispatch_authorized`, `creating`, `sent`, `reconciling` 중 하나다.
- `progressDetail`이 `client-started`, `info-inserted`, `creating`, `sent` 중 하나다.

예를 들어 `progressStep === "preparing"`이어도 `progressDetail === "creating"`이면 문서가 이미 생성되었을 수 있다.
상세 경고, 재시도·취소 대화상자, 실패 팝업은 모두 이 판정을 사용한다. 재시도·취소 가능 여부와는 별개의 판정이다.

| 수정본 확인 필요 다음 행동(기존 문구 재사용) | 제공기록지의 내용과 처리 결과를 확인하고 관리자에게 문의해 주세요. |

팝업 버튼의 기존 `확인하기` 문구는 유지한다. 제공기록지는 `failureReasonCode`로 실패 사유를 선택하며 raw 오류·연락처는 표시하지 않는다.
`PRE_SEND_RETRY_EXHAUSTED` 화면용 사유 코드는 처리 대기에 매핑한다. 기존 계약서 raw `lastErrorCode`의 상세 진행 단계 표시는 유지한다.

제공기록지의 사유는 문서 생성 가능성이 있거나 `SERVICE_RECORD_REVISION_MANUAL_REVIEW_REQUIRED`이면 코드별 사유보다 결과 확인 안내를 우선한다.
다음 행동은 문서 생성 가능성이 있으면 이폼사인 확인 안내를 우선하며, `cancellable === true`일 때만 취소를 권한다. 취소 불가이면 관리자 문의를 안내한다.
문서 생성 가능성이 없으면 `retryable === true`와 `cancellable === true` 조합에 맞는 문구를 선택한다.
재시도 불가인 경우에는 지점 소유권 오류·보관 만료·수정본 확인 필요 코드의 전용 다음 행동을 우선한다.
