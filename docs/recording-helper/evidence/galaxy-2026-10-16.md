## 기준선 관찰

사용자는 선택한 폴더가 상위 폴더가 아닌 **실제 통화 녹음 폴더 자체**라고 확인했다.
앱의 가명 observation store에서 확인한 2개 MANUAL_SCAN event는 다음과 같다.

* stage: BASELINE / grantStatus: GRANTED / listingStatus: OK.
* providerLoading: false / entryCapReached: true / entries: 200.
* change: 첫 관찰 FIRST, 다음 관찰 INCOMPLETE.

이는 폴더 읽기가 허용되고 일부 문서 메타데이터를 읽었다는 증거다. 전체 목록 수, 새 파일 부재,
누락 없음, 완전한 기준선 또는 녹음 완료의 증거가 아니다. 200개 cap을 해제하거나 기존 녹음을
옮기거나 삭제하지 않았다.

부분 목록에 실제로 포함된 특정 document의 존재·크기·mtime은 관찰할 수 있다. 그러나 새로 보인
HMAC만으로 그것이 이번 시험 녹음임을 단정하지 않는다. 사용자가 해당 시험 파일을 명시적으로
선택한 READ_PROBE 등으로 연결해야 한다. 시험 파일이 표시 범위 밖이면 별도 단일 파일 관찰
경로가 필요하며, 목록에 없다는 이유로 SAF에 노출되지 않았다고 판정하지 않는다.

## 진행 절차와 데이터 경계

사용자에게 개인정보 없는 시험 통화를 요청했다. 삼성 전화 앱의 통화 녹음이 실행되는 동안
진단 앱을 전면에 두고 통화 중 단계에서 약 20초 관찰, 통화 종료 후 통화 후 단계에서 약 20초
관찰하고 각각 중지하는 절차다. 사용자는 지금 시험 통화를 할 수 없다고 답했으므로
통화 중/후 관찰은 NOT_RUN으로 유지한다. 이를 테스트 실패나 통과로 해석하지 않는다.

통화 없이 가능한 앱 재시작 검사를 진행했다. 진단 앱만 force-stop한 뒤 다시 실행하여
별도 새 process와 LaunchState=COLD / Status=ok를 확인했다. 재시작 후 폴더를 다시 고르지 않고
사용자가 지금 스캔을 실행해 권한·목록 유지를 확인했다. 실제 store에도 세 번째 MANUAL_SCAN이
GRANTED/OK, providerLoading=false, entryCapReached=true로 추가됐다. 따라서 앱 process 재시작 후
읽기 권한과 부분 목록 접근 유지는 PASS다. 전체 목록 기준선은 여전히 INCOMPLETE다.

사용자는 현재 폴더가 맞으며 기존 녹음들이 있다고 재확인했다. 기존 녹음 한 개를 사용자가
선택해 1바이트 읽기를 수행하도록 안내했다. 이 검사는 기존 파일의 접근·읽기만 확인하며,
작성 중 녹음과 완료 녹음의 구분을 대신하지 않는다. 휴대폰 자체의 재부팅 검사는 아직 수행하지 않았다.

선택한 녹음의 1바이트는 기기 안에서 읽고 즉시 버렸다. 원본 음성의 재생·복사·전송은 수행하지
않았고, raw tree URI·private preferences는 조회하거나 복사하지 않았다.
UI 진단에는 기기 내 임시 hierarchy의 고정 컨트롤 문구·활성 상태·bounds만 사용했고,
원본 파일명·전화번호는 모델 출력이나 로컬 증거/이슈에 저장하지 않았다.
관찰 중간 확인은 진단 앱의 가명 files/observations.v1에서 상태와 개수만 출력했다.
가명 기준선은 task 임시 위치에만 보관하며 전체 고객 파일 메타데이터를 이 문서에 넣지 않는다.

새 시험 통화의 통화 중/후 노출·안정화·늦은 노출, 이름/문서 ID 변화,
