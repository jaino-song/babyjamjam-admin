# 사용자 오류 메시지

웹과 모바일의 오류 안내는 언어 설정과 관계없이 짧은 한국어 해요체로 표시한다.

## 표시 규칙

- 서버가 제공한 업무상 원인이나 검증 조건을 우선한다. 예: “서비스 날짜는 서비스 시작일보다 빠를 수 없어요.”
- 필드 이름은 사용자 용어로 바꾼다. 예: 중복 `phone`은 “연락처 정보가 이미 등록돼 있어요.”
- 원인이 없으면 확인된 HTTP 상태나 연결 오류만 설명한다. 아무 정보도 없으면 정확한 원인이 확인되지 않았다고 안내한다.
- 원본 오류, 인증 갱신·재시도 판단, HTTP 상태는 변경하지 않는다.
- SQL, 스택, 인증 정보와 원본 5xx 본문은 표시하지 않는다. 알려진 오류 코드는 안전한 고정 문구로 바꿀 수 있다.

## 적용 위치

`@babyjamjam/shared`의 `getUserErrorMessage(error, fallback?)`를 사용자에게 오류가 보이는 지점에서 사용한다. 기존 `getErrorMessage`와 `getApiErrorMessage`도 이 함수를 사용한다. 공통 API 프록시는 응답 상태를 전달하고 안전한 업무 오류만 반환한다.

영문 업무 오류는 `packages/shared/src/errors/korean-error-messages.ts`에 정확한 원문과 번역을 함께 추가한다. 새로운 검증 규칙이나 오류 코드를 도입할 때 실제 입력과 예상 문구를 테스트한다. 알려지지 않은 영어 문구를 추측해서 번역하지 않는다.

기존 오류 알림은 생성과 갱신 모두 공통 처리를 거친다. 별도 화면 오류, 폼 검증, 채팅 오류도 표시 전에 공통 처리를 적용한다. 성공 안내와 정상 대화 내용은 오류 변환 대상이 아니다.
