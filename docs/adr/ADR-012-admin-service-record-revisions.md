# ADR-012: 고정 제공 일수와 지점 수정 확정 및 문서 동기화

Status: Proposed — 사용자 제품 정책 확정, 구현 설계 독립 검토 APPROVE(2026-09-07), 사용자 실행 승인 후 Phase 0 진행 중. 2026-09-08 실제 제공 일수 분리와 완료 계약 신규 생성·재서명 정책 반영. 2026-09-07 UI 저장 검증 완료, 자동 문서 저장/출력 검증은 구현 전 필수 조건.

## Context

지점은 기존 제공기록지 전체 화면에서 제출된 일자와 내용까지 수정한다. duration은 바우처 종류와 가격 기준으로 유지한다. 고객 모달에서 확인한 실제 제공 일수 N은 duration과 달라도 되며, 미제공일이 있으면 이후 일정을 영업일만큼 미뤄 총 제공 횟수를 보존해야 한다. 같은 지점 관리자가 초안을 이어서 작업하고 고객 상세의 수정 확정에서 실제 반영한다. 계약서·영수증 서비스 기간도 바뀌어야 하며 본인부담금 수령일과 금액은 바뀌지 않는다.

## Decision

1. 관리자 로그인 및 지점 권한을 사용하는 같은 frontend 출처의 별도 최소 레이아웃을 만든다. 공개 전화번호 인증을 조작하지 않는다. 전체 기존 UI를 별도 React 패키지로 공유하고 앱별 인증/저장/라우팅을 분리한다.
2. 지점 공동 초안은 확정 데이터와 별도 저장한다. 원본/초안 버전과 확인 내역을 검증해 덮어쓰기를 막는다. 최초 날짜와 실제 서명/제출 시각은 영구 보존한다.
3. 날짜의 단일 기준은 날짜·assignmentId·scheduleId·employeeId·귀속 근거 버전을 포함하는 N개 확정 회차 배열이다. 공개 제공인력의 신규 day 저장도 이 배열의 최신 버전을 검사한다. N은 최초에는 고객 정보 모달에서 확인한 날짜의 영업일 수로 정하고, 이후 일정 이동 중에는 보존한다. duration과 다르면 기존 취소/확인 모달만 사용하며 사유나 별도 일수 입력을 받지 않는다. 실제13일·바우처15일이면15일 가격 기준을 유지한다. 기존 case는 과거 확정 회차와 배정 근거를 우선하며 확장된 외곽 날짜로 N을 재계산하지 않는다. 한국 영업일 차이를 선택 회차 이후 전체 회차에 적용해 간격·제공인력 귀속을 유지한다. 주말/공휴일, 중복, 역전, 배정 충돌, 불명확한 귀속은 확정 차단이다.
4. DB 확정은 일정·기록·배정·기간·감사 이력·고정된 수정 사본·문서 작업 의도 및 예약 작업 버전을 함께 저장한다. 모든 writer는 공통 잠금 순서를 따른다. DB와 외부 문서가 원자적으로 함께 저장됐다고 표시하지 않는다.
5. 계약 완료 전에는 기존 전자문서의 계약 기간과 영수증 서비스 기간을 모두 갱신한다. 계약 완료 후에는 기존 완료 문서를 보존하고 수정 날짜로 새 계약을 처음부터 생성하여 이용자에게 새 서명을 받은 뒤 제공기관 확인/검토로 진행한다. 원본 서명을 새 계약에 복사하지 않는다. 실제 외부 단계가 판단 기준이며 단계 이름만으로 완료를 추정하지 않는다. 완료 전에는 지원 API/임베디드 경로에서 재서명 없는 저장·출력 갱신을 검증하고, 완료 후에는 새 계약 생성·새 서명 흐름을 검증한다.
6. 제공기록지 재생성은 확정 사본과 기존 서명으로 새 발행 버전을 만든다. 양식/내용/발행/경합 버전을 구분한다. 원본 서명은 유지하고 문서 표시용 서명 날짜만 수정 제공일을 사용한다. 실제 감사 이력 날짜를 변경하거나 새 서명 동의로 표시하지 않는다.
7. 기존 전자문서 작업·청크·재시도 체계를 확장한다. 문서별 작업이 최신 수정 버전과 일치하는지 확인하고, 외부 응답 유실은 재조회로 해결한다. 실패 시 같은 버전 재시도, 구문서 webhook의 최신 상태 덮어쓰기 금지. 연동 진행/실패를 숨기지 않는다.
8. 서비스 종료일 기준 자동 계약 완료 작업과 미발송 예약 메시지는 최신 버전으로 재검증한다. 문서 연동이 미완료면 자동 완료와 오래된 영수증 전송을 보류한다. 이미 보낸 메시지를 다시 보내지 않는다. 기존 영수증 URL과 만료 정책을 유지하며 검증된 최신 이미지로 교체한다.

## Alternatives considered

- 공개 링크에 admin 옵션 추가: 서버 권한 경계를 보장하지 못함.
- 초안을 실제 기록에 즉시 저장: 수정 확정 전에 제공인력과 일정에 노출됨.
- 달력 일수만큼 이동하거나 회차 삭제: 영업일 및 고정 제공 횟수 요구 위반.
- 매번 수정 계약서 발급: 완료 전 동일 문서를 유지한다는 사용자 정책 위반.
- DB 잠금 안에서 외부 호출: 응답 유실 및 교착을 DB rollback으로 해결할 수 없음.
- UI 임시 저장 성공을 API/PDF 성공으로 간주: 서로 다른 저장/출력 상태일 수 있어 채택하지 않음.

## Consequences

추가형 schema, 공통 날짜 조회, 초안 경합 제어, 문서별 동기화 상태가 필요하다. 기존 직원 귀속이나 실제 서명 증거를 재작성하지 않는다. 외부 갱신 실패 중에도 확정 내용은 보존되며 재시도 대상이 명확하다. 이전 연동이 미완료인 동안 추가 초안 저장은 허용하되 다음 확정은 차단한다.

## Risks and validation

제공 일수 유실은 N 및 날짜 배열 불변식으로 검증한다. 다른 고객의 직원 배정과 겹치는 경우 잠금 안에서 거부한다. 자동 완료/메시지 작업의 오래된 실행과 외부 완료 경합은 버전 검사와 외부 상태 재조회로 검증한다. 외부 문서 부분 실패·중복 요청·구버전 webhook·서명 및 수령일 보존·재접속·공용 PDF/영수증 이미지 검증을 필수로 한다. 자세한 task/배포/롤백 조건은 implementation-plan.md를 따른다.
