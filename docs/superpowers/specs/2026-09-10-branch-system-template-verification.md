# 메시지 기본 템플릿과 지점별 편집 검증

## 적용 동작

- 새 지점과 수정 이력이 없는 지점은 현재 관리자 기본 템플릿을 사용한다.
- 지점의 첫 실제 수정은 전체 템플릿 내용을 한 번에 보관한다. 그 뒤에는 수정하지 않은 항목을 포함해 관리자 기본값 변경을 받지 않는다.
- 같은 내용을 다시 저장하거나 검증 실패한 요청은 수정 이력을 만들지 않는다. 수정 후 문구를 기본값과 같게 되돌려도 이력은 유지된다.
- 관리자 페이지는 공통 기본값을 수정한다. 메시지 페이지에서는 인증된 지점 구성원이 같은 편집기로 현재 지점의 문구를 수정한다.
- 메시지 페이지의 ‘관리자 페이지에서 수정’ 링크는 제거한다. 문구 편집에는 발신번호 승인이 필요하지 않으며 실제 발송 승인 조건은 유지한다.
- 목록은 서버 카탈로그 전체를 사용한다. 현재 13개이며 클라이언트의 과거 9개 목록으로 제한하지 않는다.
- 저장 요청의 지점은 인증된 세션으로 결정한다. 화면이 기억한 지점과 세션 지점이 다르면 409로 거부한다.
- 자동 발송과 수동 발송 폼은 해당 지점에 적용되는 본문을 읽는다.

## 구현 범위

기존 `SystemTemplateEditor`, 관리자 콘솔, 메시지 페이지, 시스템 템플릿 서비스/훅을 확장했다. 전역 API는 유지하고 지점 조회/수정 API를 추가했다. `branch.system_template_snapshot` JSONB 필드에 전체 문구와 커스텀 변수를 저장하며, 최초 저장과 후속 동시 수정은 트랜잭션과 지점 행 잠금으로 처리한다.

운영 데이터베이스에는 마이그레이션을 적용하지 않았다. 로컬 검사에만 별도 PostgreSQL을 사용했고 외부 문자 발송은 하지 않았다. 기존 전역 템플릿의 자동화 변수 검증은 보수적인 기존 기준을 유지한다.

## 검증 결과

- 통합 백엔드: 실제 로컬 PostgreSQL을 포함한 5개 테스트 묶음, 297개 통과.
- 프론트엔드: 7개 테스트 묶음 60개 통과. 추가 초기 렌더링 회귀 테스트 및 관련 3개 묶음 34개 통과(전체 고유 테스트 61개). 타입 검사 통과.
- 초기 렌더링 회귀 테스트는 기존처럼 쿠키를 바로 읽도록 바꾸었을 때 실패하고, 수정 복원 후 통과했다.
- 실제 로컬 로그인/지점 선택 후 권한 확인: 비로그인 401, 일반 사용자의 전역 수정 403, 다른 지점 선택 403, 이전 지점 저장 요청 409.
- 실제 관리자 화면에서 기본값 저장 → 일반 A지점 사용자 메시지 화면에서 첫 수정 → 관리자 화면에서 다른 항목 변경 → A지점 전체 유지 / B지점 최신값 반영을 확인했다. 새로고침 후에도 지점 문구가 유지됐다.
- 지점 목록 13개 표시, 관리자 수정 링크 미노출, 발신번호 승인 전 편집 가능을 확인했다. 실제 발송은 수행하지 않았다.
- 로컬 Playwright 기능 검사에서 관리자/메시지 화면의 페이지 오류는 0개였다. 1280px 화면의 본문 편집 너비는 각각 약 445px/471px, 375px에서는 약 358px이었다. 스크린샷을 직접 확인해 관리자 편집 칸이 좁아지는 배치를 수정했다.
- UI 부채 기준선은 메시지 페이지의 기존 35개 항목 위치만 갱신했다. 종류·개수의 증가를 허용하지 않았다.
- 의존성 감사는 기존 취약점 14개(low 1, moderate 5, high 6, critical 2)를 보고했다. 이번 작업은 의존성 파일을 변경하지 않았다.

기능 검사 결과는 `/tmp/bjj-template-journey-results.json`, `/tmp/bjj-template-layout-results.json`에, 테스트 출력은 `/tmp/bjj-template-backend-tests.log`, `/tmp/bjj-template-frontend-tests.log`, `/tmp/bjj-template-hydration-tests.log`에 남겼다. 로컬 경로이므로 CI나 운영 검증을 대신하지 않는다.

## 남은 승인 및 제한

`dev` 병합과 운영 배포는 별도 단계다. 최종 실제 Chrome 화면 검수에 요구된 `chrome:control-chrome` 도구/스킬은 이 세션에서 사용할 수 없었다. 위 Playwright 검사는 기능·레이아웃 보조 증거이며, 해당 스킬이 요구하는 최종 실제 Chrome 검수 통과로 간주하지 않는다. 최종 검수와 독립 검토 상태는 작업 완료 보고에서 구분한다.
